# SpectralMM: supplementary replication materials

This archive contains the existing SpectralMM source, experiment scripts,
configurations and recorded results. It uses the original two experiment entry
points. No algorithm, experiment configuration or recorded measurement was changed
for this submission archive.

## Contents

- `julia/`, `R/`, `python/`, `cpp/`: package sources and shared C++ core.
- `tools/`: package source synchronization and build utilities.
- `examples/`: package example data and scripts.
- `benchmark/run_julia.jl`: pure-Julia experiment entry point.
- `benchmark/run_python_r.py`: Python/R experiment entry point.
- `benchmark/julia/`: Julia configuration, experiment implementation and results.
- `benchmark/python_r/`: Python/R configuration, data generation, timing and export scripts.
- `benchmark/python_r/results/initial-strict-12-2026-10-15/`: selected recorded Python/R results and tables.

Git history, installed environments, compilation products, temporary runs and
unrelated archived investigations are excluded. Large synthetic design matrices
are generated by the included scripts rather than distributed in the archive.

## Requirements

Run commands from the archive root. Install Julia, Python, R, CMake and a C++17
compiler. The package supports Julia >=1.10, Python >=3.9 and R >=4.0; these are
minimum supported versions, not a claim of identical numerical results across
all versions. Python requires NumPy, SciPy, pandas, statsmodels, patsy and
threadpoolctl. R requires Rcpp, RcppEigen, Matrix, jsonlite and MASS.

```sh
python -m pip install numpy scipy pandas statsmodels patsy threadpoolctl
```

In R:

```r
install.packages(c("Rcpp", "RcppEigen", "Matrix", "jsonlite", "MASS"))
```

Keep `julia`, `R`, `Rscript` and `cmake` on PATH. Dependency installation and
initial native builds may require internet access. Use a fresh environment and
record installed versions when rerunning the experiments. Package dependency
constraints are provided in each language's package metadata.

## Experiment 1: pure Julia

```sh
julia --project=benchmark/julia benchmark/julia/setup.jl
julia --threads=12 --project=benchmark/julia benchmark/run_julia.jl \
  --output benchmark/runs/julia-paper
```

The unchanged configuration is `benchmark/julia/julia_settings.jl`:
n=10000, p=5000 predictors, plus one intercept, for both dense and sparse designs.
It requests 12 BLAS threads and five timing samples. Output consists of
`dense.csv`, `sparse.csv` and `settings.txt` in the chosen output directory.
Use `--storage dense` or `--storage sparse` to run only one design type.

The recorded results and existing paper table fragments are:

| Design | Recorded CSV | GLM table | Non-GLM table |
|---|---|---|---|
| Dense | `benchmark/julia/results/scaling_results.csv` | `dense_glm.tex` | `dense_nonglm.tex` |
| Sparse | `benchmark/julia/results/scaling_sparse_results.csv` | `sparse_glm.tex` | `sparse_nonglm.tex` |

All four table fragments are in `benchmark/julia/results/`. The Julia runner
writes CSV files; it does not regenerate these historical table fragments.

## Experiment 2: Python and R using the C++ backend

```sh
julia --project=julia -e 'using Pkg; Pkg.instantiate()'
python benchmark/run_python_r.py \
  --settings benchmark/python_r/settings.json \
  --output benchmark/runs/python-r-paper
```

The unchanged configuration uses n=2000, p=1000 predictors plus one intercept,
dense and sparse designs, and 12 requested threads. The runner builds the local
C++ core, installs the bundled R package into an isolated library, generates
shared synthetic data and runs both languages. The input generator is
`benchmark/python_r/family_performance.jl`. Python and R use the same generated
inputs and initial coefficients. Random seeds and family parameters are in the
included experiment scripts; the settings files control sizes and tolerances.

Outputs include `python.csv`, `R.csv`, raw timing samples, repeat measurements,
configuration and provenance records. `latex/` holds initial-run tables;
`latex_repeat/` holds verified repeat timings with matching initial GLM baselines.
Always use a new output directory. Do not combine measurements from different runs.

Recorded paper results are in:
`benchmark/python_r/results/initial-strict-12-2026-10-15/`.
There are four tables per language: dense/sparse x GLM/non-GLM. Existing LaTeX
files are in its `latex/` directory. To regenerate them from those recorded CSVs:

```sh
python benchmark/python_r/export_latex.py \
  --results benchmark/python_r/results/initial-strict-12-2026-10-15 \
  --source initial
```

This overwrites only derived tables/reports in that directory. Use a copy if you
want to preserve every original file. The standalone `performance_tables.tex`
can be compiled with LaTeX or uploaded to Overleaf.

## Interpretation and practical requirements

Timings depend on CPU, BLAS implementation, threads, memory and software versions;
identical elapsed times are not expected on another PC. A 10000x5001 Float64
matrix alone requires about 400 MB. Cholesky and reference fits need additional
dense workspaces, including with sparse input. Allow several GB of free RAM.
No machine-independent full-experiment runtime is asserted.

Each implementation retains its configured stopping rule. Julia may accept
stalled steps; the Python/R native configuration disables step-based acceptance.
Official GLM fits use deviance-based stopping, while reported gradient norms are
evaluated separately. The existing Julia benchmark hard-codes GLM.jl's
`Converged=true`; it must not be interpreted as an independently verified gradient
criterion. This behavior is documented here rather than changed for packaging.

The historical Python/R results have incomplete binary provenance, as explained
in their original README; the historical Julia CSVs also lack a complete source
and environment fingerprint. These limitations are retained explicitly. The
archive does not retrospectively certify an exact binary identity or guarantee
that current-source reruns reproduce every historical coefficient or timing.

For further parameter definitions and commands, see `benchmark/README.md` and
`benchmark/python_r/README.md`. Their references to other historical archives may
refer to files intentionally omitted from this focused submission package.
